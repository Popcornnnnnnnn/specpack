# SpecPack — 可重建的个人软件，而非克隆品

[English](README.md) · **简体中文**

> 把**配方与不变量**开源，让每个人都能做出属于*自己*的那一份。

AI 智能体几乎能构建任何小型软件。结果就是大量一次性应用泛滥成灾——“slop”：仅仅因为*能做出来*就被造出来，一周后便无人问津，或者只以迎合单一作者品味的成品代码形式发布。

SpecPack 探索的是另一种开源交付单元：

**发布一个精简的配方包——核心不变量、来之不易的踩坑记录以及个性化访谈——让其他人能把它交给*自己的*智能体，构建出贴合*自己*工作流、交互界面与审美的版本。**

两个智能体重建同一个配方包时，**不应该产出完全一样的双胞胎**。它们应当守住相同的核心事实，同时在 UI 形态、视觉品味、技术栈和附加功能上自由发挥。

## 什么适合放进 SpecPack

SpecPack 最适合**可重新生成、偏重 UI 或工作流的个人工具**（`< 3 天`、`< 50 次对话` 或 `< 50M tokens`）：

- **非常适合：** 菜单栏小工具、本地开发控制面、个人仪表盘、分诊/审核辅助工具，或不同人确实需要不同界面与风格的强交互工作流。
- **不适合：** 纯单一用途的 CLI 与库（请直接分享如 `brew install` 之类的标准可复用软件包），或依赖专有数据、支付与实时多用户网络效应的系统（请直接维护已发布产品）。

## 配方包的三层结构（v0.2）

```
my-pack/
  pack.yaml       # 清单：名称、format_version、预算与实测运行记录
  SKILL.md        # 默认自由的指令 + 个性化访谈（Personalisation Interview）
  spec.md         # 锁定核心：约 5–15 条可测试的不变量（[1.1]）+ 非目标
  decisions.md    # 建议参考：参考选型、踩坑与死胡同、品味取舍
  examples/       # 具体的 场景/输入 -> 预期结果 样例夹具
  reference/      # 一位创作者的截图/演示，仅作灵感参考（非像素级硬性要求）
  tests/          # 结果/场景不变量测试（JUnit XML -> eval/score.py）
  eval.md         # 如何验证核心不变量与所选个性化配置
```

只有 **`spec.md`（核心不变量 + 非目标）** 是严格契约：
- `decisions.md` 将你踩过的坑和做过的取舍作为*建议*分享，而非命令。
- `reference/` 以情绪板形式展示一位作者的品味，绝非像素级门槛。
- `SKILL.md` 在编码前运行轻量级的 `/grill-me` 式**引导品味访谈（Guided Taste Interview）**——一次只问一个产品/UX 问题，附带推荐默认值且不含底层技术黑话——让重建出的软件真正契合用户的工作方式。

参阅 [FORMAT.md](FORMAT.md)、[校验器](eval/validate.py)、[JUnit/JSON 评分器](eval/score.py)、[洁净室试验脚手架](eval/prepare_run.py)、[并排对比工具](eval/compare.py)、[配方包提炼技能](skills/harvest-specpack/SKILL.md) 以及参考配方包（[Port Tools](examples/port-tools/) 与 [Signal](examples/signal/)）。

## 实验内容

不同的智能体宿主在**仅获得一个配方包**（没有任何原始源码）的情况下，能否构建出**各具特色、量身定制的应用**，同时干净且低成本地守住**每一条核心不变量**？

实验协议与结果记录：[experiment/](experiment/)

1. 挑选一个真实的工作流/强 UI 工具（例如本地端口与开发控制面）。
2. 从构建过程中提炼出一个精简的配方包——剥离实现绑定，只留下不变量、踩坑记录与品味决策。
3. 将配方包在冷启动状态下交给不同的宿主（`Codex`、`Claude Code`、`Cursor`、`Antigravity`、`OpenCode`）并搭配不同的用户个性化选择。
4. 记录：宿主、模型、选定的界面/风格、耗时、轮次、token 消耗，以及真实测试执行得到的 `Invariants %`。
5. 同时公开成果与差距——任何遗漏的不变量或意外偏移都会帮助改进格式规范。

## 核心原则

1. **不变量优先于蓝图。** 锁定*必须保持为真的边界*；把*外观和运行方式*留白给用户决定。
2. **警示陷阱，而非强加选型。** 通过 `decisions.md` 分享踩过的坑，让重建者不必重蹈覆辙，同时不强制指定技术栈。
3. **先个性化，再写代码。** 没有经过刻意界面/品味选择的重建，只是速度更慢的抄袭。
4. **用测试证明不变量。** 场景与结果测试才是关键；截图仅供灵感参考。
5. **如实报告成本。** 每次重建都如实记录界面形态、耗时、轮次、token 消耗与差距。

## 当前状态

**v0.2** — 围绕“默认自由”重构（`spec.md` 核心不变量、建议性质的 `decisions.md`、`SKILL.md` 逐题式引导品味访谈、`reference/` 情绪板），并由 `eval/validate.py` 与 `eval/score.py` 提供校验支持。仓库中包含 **[Port Tools](examples/port-tools/)**（首个完整提炼的重 UI 参考配方包）以及 **[Signal](examples/signal/)**。
